# Analytics operations

This repository uses a local, privacy-minimised analytics bridge so aggregate
site data can be reviewed without relying on the Microsoft Clarity or
Cloudflare dashboards.

## Sources and roles

- **Cloudflare GraphQL Analytics API** is the traffic baseline. It supplies
  aggregate visits, requests, public paths, device types, and response-status
  families for `samfa12.com`.
- **Microsoft Clarity Data Export API** is the opt-in behaviour sample. The
  bridge requests aggregate URL, device, and source dimensions plus Clarity's
  interaction metrics. It never downloads session recordings.
- The Pocket Audio handoff Worker, KV records, and transferred song payloads are
  outside this analytics pipeline.

Clarity covers only visitors who allowed analytics. Do not use it as the total
traffic count or generalise from it when the export has no rows.

## Private local configuration

Copy `.env.analytics.example` to `.env.analytics`. The real file is ignored by
Git and must never be committed.

Required values:

- `CLARITY_API_TOKEN`: generated by a Clarity project admin under
  **Settings > Data Export**.
- `CLOUDFLARE_API_TOKEN`: a custom token restricted to the `samfa12.com` zone
  with these read-only permissions:
  - **Account > Account Analytics > Read**
  - **Zone > Analytics > Read**
  - **Zone > Zone > Read**
- `ANALYTICS_HOSTNAME`: normally `samfa12.com`.
- `CLOUDFLARE_ZONE_ID`: optional; the collector resolves it using Zone Read
  when omitted.
- `CLOUDFLARE_LOOKBACK_DAYS`: defaults to and is capped at `8` for the current
  zone plan.

Rotate either token in its provider dashboard and replace only the matching
value in `.env.analytics`. Run `npm run analytics:check` after rotation.

## Commands

```bash
npm run analytics:check
npm run analytics:collect
npm run analytics:report
npm run test:analytics
```

`analytics:collect` writes a timestamped JSON snapshot beneath
`.analytics/snapshots/`. `analytics:report` writes
`.analytics/reports/latest.md`. Both directories are local and ignored.

A snapshot contains aggregate data only. URL query strings and fragments are
removed before writing. Tokens, individual visitor identifiers, session
recordings, and Pocket Audio handoff data are not written.

## Current API boundaries

Verified against the live project on 2026-07-28:

- Clarity exports only the previous 1-3 days and permits at most 10 requests
  per project per day. The bridge makes one one-day request per daily
  collection.
- This Cloudflare zone accepts at most one day per GraphQL query and exposes an
  eight-day rolling history for the selected dataset. The collector requests
  one-day slices and merges them locally. It leaves a five-minute margin at the
  oldest boundary so the request cannot age past the retention limit while the
  batch is running.
- Rolling Cloudflare snapshots overlap. The report retains the largest observed
  visit and request totals for each calendar date so a later partial boundary
  day cannot replace an earlier complete day.
- API calls retry transient connection resets, rate limits, and retryable 5xx
  responses up to three times.

Revalidate these limits after a Cloudflare plan change or API schema change.

## Automated schedule

The Codex desktop app currently has two active local automations:

- `Collect Samfa12 analytics`: daily at 08:00 Australia/Sydney; collects a
  snapshot and refreshes the report. It notifies only on failed runs.
- `Review Samfa12 analytics`: Mondays at 08:15 Australia/Sydney; reviews the
  aggregate report and gives page-level recommendations.

These schedules live in the Codex app, not in Git. The scripts remain usable
manually if an automation is paused or unavailable.

## Interpretation rules

- Compare seven days with the preceding seven only when both periods contain
  seven accumulated calendar days.
- Treat Clarity as an opt-in diagnostic sample, not the traffic baseline.
- Treat aggregate 4xx counts as triage signals: bots, probes, and missing assets
  may be included. Do not call a public page broken without path-level evidence.
- Investigate small 5xx totals only if they recur or align with a reproducible
  page/app failure.
- Keep mobile and desktop validation in scope when their measured visit shares
  are comparable.
- Prefer no recommendation over a claim unsupported by the available sample.

## Troubleshooting

- `Analytics configuration is incomplete`: add the named values to the ignored
  `.env.analytics` file.
- `does not have permission ... zone.analytics.read`: add
  **Zone > Analytics > Read** to the Cloudflare token.
- A Cloudflare range or retention error means the plan boundary changed. Update
  the capped lookback and tests; do not silently discard failed slices.
- A transient `ECONNRESET`, HTTP 429, or retryable 5xx is retried automatically.
  Persistent failures remain visible and do not create a partial snapshot.
