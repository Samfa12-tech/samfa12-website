## Cause and correction

`Soundscape.start()` was called only by dive/practice launch and dive resume.
The fresh harbour and newly added boat travel therefore never created or
unlocked Web Audio. The retained published bundle reproduced boat launch with
`context: not-started`, zero scheduled steps and no motor. Its SHA-256 matches
the tracked hosted bundle:
`75c81aa6e8a8184504035bff22dea95cc7f41ecb88f401ede01af32da8983e4b`.

Boat travel also supplied no engine state to the soundscape: the scooter motor
was gated on an active dive. The old three-second `boat-engine` effect is a
one-shot dive event, not a continuous travel engine.

- The first menu pointer/key/touch interaction starts the existing Room for
  Life score; listeners remain for denied unlocks and interrupted contexts.
  No sound is expected before a browser-authorized first interaction.
- Boat resume/launch explicitly starts audio too, including controller-driven
  UI activation where the browser permits audio. Travel supplies boat speed to
  a second fixed two-oscillator instance of the existing motor, tuned lower.
  Idle, forward/reverse speed, effect mute, pause, dive and harbour exits own
  its gain. It creates no per-frame audio nodes.
- Boat pause now participates in audio pause. Shared gain updates preserve
  pause/mute state when settings change and cancel deferred warning restores.
- Hidden/pagehide states fade every bus to zero and silence motors. Visibility
  return restores the appropriate menu/paused levels; gameplay remains paused.
  Hidden music scheduling stops, and the existing clock catches up on return.

The editable PCS score, voices, local asset paths, settings keys, save schema,
game rules and hosted game files are unchanged. Explicit saved zeros remain
zero. No new media, dependencies, copied project or worktree was created.
